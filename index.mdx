TaskMaster is a local CLI orchestrator that runs a fixed five-agent AI coding team — planner, builder, tester, validator, and documenter — directly in your terminal. Every agent lives in a named tmux pane, all state persists in `~/.taskmaster/state.sqlite`, and OpenCode provides the AI runtime. Give TaskMaster a goal and it produces a validated task plan, then executes the first ready builder task without leaving your shell.

## How TaskMaster works

<Steps>
  <Step title="Check your environment">
    Run `taskmaster doctor` to verify tmux, git, and AI runtimes (Cursor, Codex, OpenCode, Claude) are installed and authenticated.
  </Step>
  <Step title="Start the demo session">
    Run `taskmaster demo` to open a tmux session with all five agent panes. The planner, tester, validator, and documenter run as mock agents; the builder connects to OpenCode.
  </Step>
  <Step title="Plan a project">
    Run `taskmaster plan "Build Tic Tac Toe"` to invoke the planner agent. TaskMaster validates the generated `ProjectPlan`, inserts the task DAG into SQLite, and immediately executes the first ready builder task.
  </Step>
  <Step title="Monitor and manage">
    Use `taskmaster status` to inspect agent lifecycles, `taskmaster attach` to return to the tmux session, and `taskmaster demo restart <role>` to recover a crashed pane.
  </Step>
</Steps>

## Key features

<CardGroup cols={2}>
  <Card title="Five Fixed Agents" icon="users">
    Planner, builder, tester, validator, and documenter. No dynamic hiring, no extra processes — delegation creates tasks, not new agents.
  </Card>
  <Card title="tmux-First Layout" icon="grid-2">
    Two windows: an `agents` window with a 2×2 grid and a `support` window for the documenter and event log. Full terminal visibility at all times.
  </Card>
  <Card title="SQLite State" icon="database">
    All tasks, runs, sessions, events, and provider config live in `~/.taskmaster/state.sqlite`. Override the path with `TASKMASTER_HOME`.
  </Card>
  <Card title="Validated Plans" icon="circle-check">
    The planner writes a `ProjectPlan` JSON. TaskMaster validates structure, detects dependency cycles, and rejects invalid plans before touching the task DAG.
  </Card>
  <Card title="Atomic Ownership" icon="lock">
    `claimTask` is a compare-and-set transaction. One task has one active owner. A conflicting claim fails immediately — no silent double-execution.
  </Card>
  <Card title="Secure Secrets" icon="shield-halved">
    Credentials stay in `~/.taskmaster/secrets` at mode `0600`. The project repository never receives key material.
  </Card>
</CardGroup>
